# 序言 · 生产首发计划 v3

日期：2026-09-12

状态：产品方向已确认；R0–R2 的本地实现已启动，真实 Timeline 与 OAuth 验收待外部配置

依据：产品负责人确认首要目标是尽快打通“真实用户 → 真实项目 → 真实 Timeline 数据 → 模型生成快照”的生产链路；缓存和跨会话持久化不再阻断首发。生产环境很可能部署在阿里云，具体云产品待部署阶段确认。

## 1. 首发目标

首发只验证一条真实、可用、可授权的纵向链路：

```text
公司 OAuth 用户
  → 进入真实项目
  → 与模型自由对话
  → 模型按需调用 Timeline Agent Support 受控读写数据源
  → 服务端核对来源并生成快照候选
  → 统一协议、完整性和运行边界校验
  → 当前会话内展示真实数据快照
```

首发允许每次请求重新取数和重新生成，不要求缓存命中、active 指针、TTL、跨会话历史回放或模型离线回放。没有持久化时，页面必须明确说明刷新后结果可能消失，不能展示“已保存”“历史可回放”或“命中缓存”等状态。

## 2. 当前基线

以下能力视为当前研发基线，后续只做回归和必要修复：

1. GUI：项目群聊、项目切换、成员和上下文入口、快照挂载及移动端／键盘基础交互已具备。
2. 快照：统一 manifest、query、任意 MIME 数据、H5 表现层、hash、校验器和隔离 viewer 已具备。
3. 模型：DeepSeek 通过服务端 Agent Runtime 使用，服务端密钥、输入限制和错误处理已具备。
4. 自由对话生成快照：同一 Agent Runtime 处理普通文本与工具调用，并通过 `submit_snapshot` MCP 提交严格 `SnapshotDraft`；宿主继续生成受信字段并负责动态展示。

现有 D1／R2、Drizzle schema、run 和动态目录代码是已经验证过接口形状的可选原型。保留其存储边界，但不把 Cloudflare 绑定、真实迁移或跨请求回放列为首发依赖。

## 3. 首发范围与顺序

### R0 · 冻结 1–4 基线

- 审查并提交当前 P2 本地改动，修正文档和 README 的事实偏差。
- 用真实模型跑最小固定样本，确认普通对话和至少两种快照表现仍可用。
- 固定 Agent Runtime 版本并验证无工作区工具、无会话持久化、请求级 MCP 和失败关闭；不得回退到普通 chat completion。
- 保留全部快照安全反例和浏览器隔离回归。

退出条件：1–4 的代码、测试和产品体验都可以作为后续真实链路的稳定基线。

### R1 · Timeline Agent Support 受控读写接入

- 按实际协议完成能力发现、鉴权、分页、超时、限流和错误分类。
- 数据源凭据仅在服务端配置；禁止进入前端、模型提示词、日志或快照。
- 服务端工具层限定项目上下文授权的 HTTPS 范围；允许 GET、登录 auth POST、受校验 change-set 创建与带幂等键 commit，禁止直接 PATCH／PUT／DELETE 和其他 POST。模型不能扩大权限或自行声明操作成功。
- 将原始响应转换为有来源的工具结果，记录 source ID、revision（若有）、observedAt 和缺失字段。
- 从 Timeline 真实数据生成至少两类可核对快照；逐字段对照来源，不用 dummy 补齐未知业务事实。

退出条件：固定测试问题能稳定取得 Timeline 真实数据并生成协议合规快照；用户明确的变更可通过 change-set 幂等提交并回读核验；无越权写入、无秘密泄露、无伪造来源。

### R2 · 项目数据全真替换

- 项目由用户随时创建、重命名和删除；项目对话与项目上下文是唯一项目状态，删除时级联清理。
- 项目上下文保存背景以及 Timeline 地址、board ID、访问密码；原始上下文是唯一配置，宿主只在调用模型前生成脱敏副本，不维护独立项目或连接注册表。
- 项目上下文只作为 DeepSeek 的额外背景，不限制聊天主题；普通问题无论是否与工作相关都直接回答。
- 删除生产路径对硬编码项目、成员、示例消息和 dummy 数据的依赖；fixture 只保留在测试或明确标注的演示入口。
- 公司 OAuth 接入后按用户和项目成员关系控制谁能查看和修改项目上下文；不使用部署级项目 allowlist 代替最终授权。

退出条件：目标生产项目页面和快照中不再出现模拟业务数据；上下文、数据源范围和展示结果都能追溯到真实配置或 Timeline 响应。

### R3 · 公司 OAuth 与真实授权

- 接入公司 OAuth，服务端校验 issuer、audience、签名、过期时间、state／nonce 和回调地址。
- 由 OAuth 身份映射真实用户和项目成员关系；移除生产环境中可伪造的身份 header／前端身份选择。
- 每次聊天、工具取数和快照加载都检查当前用户、项目成员关系及 Timeline 数据可见范围。
- 覆盖未登录、过期登录、跨用户、跨项目、成员移出、权限撤销和回调攻击反例。

退出条件：用户身份和项目访问范围全部来自可信 OAuth 与服务端授权；严重越权和秘密泄露用例为零。

### R4 · 阿里云部署适配与发布准备

- 将 HTTP 入口、环境变量／密钥、身份和可选存储放在平台适配层后；业务生成链路不依赖 D1/R2 API。
- 确认阿里云运行形态、域名、TLS、OAuth 回调、出站访问、超时、并发、日志脱敏和密钥托管。
- 阿里云运行环境必须支持 Node 子进程并随镜像安装锁定版本的 Claude Code Runtime；若所选产品不允许子进程，必须改用等价的常驻 Agent Runtime 服务，不能回退为手写模型循环。
- 首发默认使用无状态生成；若平台运行需要临时对象，仅使用带生命周期和严格作用域的临时存储，不承诺历史回放。
- 建立健康检查、构建产物、配置清单、最小审计日志、回退版本和发布检查表。

退出条件：在与生产一致的阿里云预发布环境完成真实 OAuth、真实项目、真实 Timeline 和真实模型的端到端验收。

### R5 · 小范围生产发布

- 先向明确授权的内部用户开放，观察模型错误、数据源失败、快照校验失败、延迟和费用。
- 页面诚实展示生成中、生成失败、来源时间和“刷新后可能消失”的边界。
- 通过发布阻断项后再扩大范围；首发不以缓存命中率或历史回放作为成功标准。

退出条件：真实用户可以在生产项目内自由对话，并从授权 Timeline 数据生成可核对快照；无已知 P0/P1 安全或数据真实性问题。

### R6 · 发布后优化：持久化与缓存

按照真实流量、延迟和 token 成本决定优先级：

1. 先做快照和消息引用持久化，恢复刷新／跨会话回放和模型离线回放。
2. 再做幂等运行恢复、查询身份、active、TTL 和同查询生成协调。
3. 最后按证据加入服务端热缓存、浏览器缓存和淘汰策略。

存储选型在阿里云架构确定后决定。现有 D1/R2 适配器可作为行为参考，但数据库和对象存储必须可替换，不能让快照协议依赖某一家云厂商。

## 4. 首发阻断门槛

以下任一情况阻断生产发布：

1. 生产页面或模型输出把 dummy／硬编码数据说成真实 Timeline 数据。
2. 未经用户明确要求的 Timeline 写操作可发生，或模型能绕过 change-set、幂等键、工具白名单扩大方法或数据范围。
3. 数据来源、观察时间和缺失信息无法追溯，或业务结论与源数据不一致。
4. 用户身份可由客户端伪造，或跨用户／跨项目请求能读取数据或生成结果。
5. 模型、OAuth 或 Timeline 密钥进入前端、提示词、快照、普通日志或错误响应。
6. 未通过统一校验的快照可以在 viewer 中执行。
7. 恶意 H5 能访问宿主、外传数据、导航或加载远程依赖。
8. 模型／数据源失败被展示为成功，或页面暗示未实现的保存、历史、缓存能力。
9. 阿里云预发布环境未完成真实 OAuth + Timeline + 模型的端到端验证和回退演练。

缓存、跨会话持久化、自动记忆、完整消息历史、多人实时同步和管理后台不阻断首发，但界面和文档必须如实说明其缺失。

## 5. 近期执行包

按以下顺序开始：

1. R0：冻结当前 1–4 基线并建立提交检查点。
2. R1：通过 Claude Code Agent Runtime 的请求级 MCP 完成 Timeline 协议探测、真实读取和受控 change-set 最小写入。
3. R2：把目标项目从 dummy／前端内存替换为 OAuth 管理的真实用户项目及其唯一上下文。
4. R3：取得公司 OAuth 的 issuer、client ID、回调与成员映射规则后完成认证授权。
5. R4/R5：确定阿里云运行产品后做预发布和小范围上线。

每个阶段更新 `docs/STATUS.md`、`docs/BACKLOG.md` 和对应测试证据；未执行的检查不得记为通过。
