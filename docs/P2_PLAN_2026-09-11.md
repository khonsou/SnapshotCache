# 序言 · P2 开发计划：Agent 动态生成快照

状态：**Ready，已获产品确认**

日期：2026-09-11

依赖：P1 快照协议、校验器、隔离 viewer 与稳定引用

范围来源：PRD、DEVELOPMENT_PLAN_2026-09-11、SNAPSHOT_SPEC、VIEWER_PROTOCOL、ADR-0001、ADR-0002

## 1. 已确认的产品与技术决定

1. P2 使用现有 Sites 项目和 Cloudflare Worker 运行形态；结构化目录使用 D1，完整快照字节使用 R2。
2. 快照按需生成：用户明确要求，或请求明显需要结构化展示时才生成；普通交流继续只返回文本。
3. P2 不提前持久化完整群聊历史。页面刷新后，用户从“本项目生成记录”按稳定引用重新打开快照；完整消息恢复属于 P3。
4. P2 不实现缓存命中、active、TTL、查询复用、刷新协调或淘汰，这些仍属于 P4。
5. P2 只使用明确标注的 dummy 数据或用户在本轮提供的数据，不接入 Timeline，也不声称已真实取数。
6. 本计划获批不代表发布授权；开发、测试和本地预览可推进，线上版本与访问范围保持不变。

## 2. 当前基线

P1 已完成自动验收，待产品体验验收：

- 19 项 Node 测试通过。
- 18 项浏览器测试通过，覆盖 Chromium 与 WebKit。
- 7 个真实文件形式的 dummy 快照包通过 schema、scope、资源、字节、hash、引用与 web runtime 校验。
- 现有文本模型代理、群聊外壳、项目与成员交互仍可工作。

P2 开工时的事实边界：

- `server/api.mjs` 仅返回文本，system prompt 明确声明不能生成快照。
- 快照资源和 catalog 在构建期内联；前端只认识固定 dummy 目录。
- 项目、成员和聊天消息仍在浏览器内存中。
- D1、R2 尚未在 `.openai/hosting.json` 声明，也没有迁移或动态资源路由。
- 当前 P1 工作位于基线提交之后，正式实现 P2 前必须建立可恢复的 Git 检查点。

## 3. P2 目标

用户提出需要结构化展示的问题后，序言能够根据本轮允许使用的数据动态生成新的完整快照候选；可信服务端负责分配身份、校验、持久提交和授权读取；既有 viewer 展示结果。模型离线时，已提交快照仍可按 ID 回放。

完整流程：

```text
请求
  → 服务端确认身份和项目作用域
  → 建立 run 与幂等记录
  → 判断文本回答或快照生成
  → 模型输出 SnapshotDraft 候选
  → 服务端组包、预算检查和统一校验
  → 最多一次结构化修复
  → R2 写入不可变资源
  → D1 事务登记 committed 快照与消息引用
  → 返回 reply + snapshotRef
  → 前端通过鉴权路由加载并再次校验后运行
```

## 4. 不变量与信任边界

1. 模型只能产生候选内容，不能指定可信 `snapshotId`、scope、创建时间、manifest hash、提交状态、命中状态或权限结论。
2. `snapshotId`、`runId`、`messageId`、时间、scope、query 来源信息和所有 hash 均由服务端生成或核对。
3. 候选必须复用 P1 的 `packSnapshot()` 与 `validatePackage()`；不建立第二套打包或验证逻辑。
4. D1 中的 `{snapshotId, manifestHash, scope, status, objectPrefix}` 是可信目录。包内自报 hash 不能授予信任或访问权。
5. 只有所有 R2 对象写入完成并经服务端核对后，D1 才能登记 `committed`。没有 committed 目录记录的 R2 对象不可读取或引用。
6. 已提交 ID 对应的 manifest 和资源字节永不覆写。修改数据、H5、绑定或初始状态必须创建新 ID。
7. 读取 manifest 和任一资源时都重新检查当前用户和项目作用域；hash 不是权限凭据。
8. 明确要求快照的请求若生成失败，必须报告失败，不能静默伪装为成功文本回答。自动判定生成时可返回文本并明确标注快照未生成。
9. 幂等保证覆盖本产品的 run、消息引用和快照提交。供应商不支持幂等调用时，不承诺异常中断后绝对不重复计费。
10. 模型输出、网页、外部文件均不能修改服务端权限、预算、来源或提交规则。

## 5. P2 支持的生成契约

模型输出严格的 `SnapshotDraft`，最小字段包括：

- `mode`: `text` 或 `snapshot`。
- `reply`: 向用户说明结果、来源边界或失败原因的文本。
- `title`: 快照标题。
- `datasets`: 数据集描述与资源内容，仅允许声明支持的 MIME 和文本／字节编码形式。
- `presentation`: 自包含 HTML、bindings 及可选 initial state。
- `notes`: 候选对缺失信息、假设和 dummy 来源的声明。

服务端独立构造 query，并把本轮问题、intent 版本、允许的数据来源、观察时间和 dummy／user-provided 标记写入 query。模型不能覆盖 query 身份。

P2 的 HTML 仍严格服从 web/1 子集：

- 单个自包含 HTML 入口。
- 内联 CSS 与经典 JavaScript。
- 数据只能通过 `window.Snapshot` bindings 读取。
- 拒绝外链脚本、module、iframe、form、远程 URL 属性、主动跳转和未声明依赖。
- 沿用 manifest 128 KiB、单资源 1 MiB、总资源 4 MiB、最多 64 个资源的预算；超限拒绝，不截断后提交。

校验失败时只把经过清理的结构化错误代码回喂模型，最多修复一次。第二次失败即结束 run，不保存候选包。

## 6. 持久化设计

### 6.1 Sites 绑定

- D1 绑定名：`DB`
- R2 绑定名：`BUCKET`
- 模型凭据继续使用 Sites secret，不进入源码、迁移、快照、提示词或日志。

### 6.2 D1 最小表

`snapshot_runs`

- run ID、当前用户、项目键、幂等键、请求模式、状态。
- 模型、模型配置版本、生成契约版本、开始／结束时间。
- 错误分类、修复次数、最终 snapshot ID。
- 唯一约束：当前用户 + 项目键 + 幂等键。

`snapshot_catalog`

- snapshot ID、当前用户、项目键、manifest hash、R2 object prefix。
- committed 时间、来源类别、模型与生成契约版本。
- 只保存已提交记录；snapshot ID 唯一且不可更新为另一份内容。

`message_snapshot_refs`

- message ID、当前用户、项目键、snapshot ID、manifest hash、创建时间。
- 用于当前回复和“本项目生成记录”，不代表完整群聊历史已经持久化。

迁移通过 `db/schema.ts` 和 Drizzle 生成并检查。运行时只执行准备语句，不在请求处理中创建或修改表结构。

### 6.3 R2 对象布局

```text
snapshots/<snapshotId>/manifest.json
snapshots/<snapshotId>/<resource path>
```

对象前缀由服务端生成。写入顺序为资源后 manifest；全部写完后重新核对长度与 hash，再提交 D1 目录记录。中断留下的孤立对象没有目录记录，因此不可见；清理策略留到 P4，但 P2 必须能够识别它们。

## 7. API 与表现层

### 7.1 聊天响应

`POST /api/chat` 保留现有文本兼容性，并可增加：

```json
{
  "reply": "……",
  "runId": "……",
  "snapshotStatus": "generated",
  "snapshotRef": {
    "snapshotId": "……",
    "manifestHash": "……"
  }
}
```

请求增加服务端可校验的项目键、`idempotencyKey` 和可选 `responseMode: auto | text | snapshot`。默认 `auto`；用户明确要求生成时前端发送 `snapshot`。

### 7.2 动态快照路由

- `GET /api/snapshots/:snapshotId/manifest`
- `GET /api/snapshots/:snapshotId/resources/:resourceId`
- `GET /api/projects/:projectKey/snapshots`：返回当前用户在该项目的生成记录。

资源路由以 resource ID 解析 D1 catalog 和 manifest，不直接信任任意路径参数。每个路由都检查平台身份和项目作用域，并沿用 attachment、nosniff、CSP 与缓存禁止头。

### 7.3 前端

- 固定 dummy picker 和构建期目录继续保留，作为 P1 回归入口。
- `snapshot-viewer` 接受服务端返回的动态引用；仍在浏览器侧核对 manifest hash、scope、资源字节和 runtime 子集。
- 新生成结果在当前消息中展示。
- 刷新后从“本项目生成记录”重新打开；不伪装成完整聊天历史恢复。
- P2 只显示“生成中／已生成／生成失败／历史加载／不可用”，不显示缓存命中或新鲜度状态。

## 8. 实施顺序

### P2-0 · 基线与决策（0.5 天）

- 建立 P1 Git 检查点与本地备份。
- 接受 ADR-0002。
- 更新 BACKLOG，将 P2 任务置为 Ready／Doing。
- 验收：P1 全量检查仍通过，工作区可明确区分 P1 与 P2。

### P2-1 · 生成契约可行性（1 天）

- 拆出模型适配、prompt、候选解析和 intent 判断。
- 用固定样本覆盖看板、报告、空数据、边界数据和纯文本。
- 真实模型试验与默认 mock 测试分离，记录首次与一次修复后的合规率、字节量和失败类型。
- 验收：候选能够被稳定解析；服务端字段不能被模型覆盖；普通文本回归通过。

### P2-2 · 动态持久化纵向切片（1.5 天）

- 声明 D1／R2 绑定，新增 schema 与首个迁移。
- 先用确定性候选跑通 pack → validate → R2 → D1 → API → viewer。
- 保留静态 dummy 路由。
- 验收：生成一个非 catalog ID，刷新后从生成记录加载；模型离线不影响回放。

### P2-3 · Agent 生成与提交编排（1.5 天）

- 接入按需意图、结构化候选、预算和一次修复。
- 加入 run 状态、幂等与错误分类。
- 记录真实模型、配置版本、生成契约版本、耗时和结果大小。
- 验收：不同展示要求产生两种结构明显不同的有效页面；失败候选不可见。

### P2-4 · 前端状态与生成记录（1 天）

- 聊天消息接入动态 `snapshotRef`。
- 增加生成中、失败、重试和项目生成记录入口。
- 保留键盘、移动端、项目切换和原文本聊天体验。
- 验收：新旧引用稳定，目录失败时不创建空 iframe。

### P2-5 · 安全、评测与验收（1.5–2 天）

- 完成 D1／R2 集成测试、API 授权测试、浏览器隔离反例和模型评测基线。
- 回归 P1 全部测试。
- 更新 STATUS、BACKLOG 和 `docs/testing/P2_ACCEPTANCE.md`。
- 不发布；提交产品体验验收。

预计总量：6–8 个有效开发日。每个里程碑结束后根据真实证据重估，不用压缩测试维持原估算。

## 9. 测试与阻断门槛

以下任一失败都阻断 P2 完成：

1. 跨用户或跨项目请求能读取 manifest、资源或生成记录。
2. 篡改资源、可信 hash 不符、缺件、额外文件或同 ID 不同字节未被拒绝。
3. 模型能够覆盖服务端生成的 ID、scope、query 来源、hash 或提交状态。
4. 含外链脚本、module、iframe、form、远程 URL、网络外传、自导航或宿主读取的 H5 可以运行。
5. 超预算候选被截断后提交，或失败产生可见半包。
6. 明确要求快照时生成失败却展示为成功文本结果。
7. 同一幂等键创建多个本地 run、消息引用或 committed 快照。
8. 模型离线时已提交快照不能按 ID 回放。
9. 动态快照刷新后不能从项目生成记录重新打开。
10. P1 的 19 项 Node、18 项浏览器检查或 7 个 fixture 校验回归失败。
11. 响应、日志、D1、R2、提示词或快照资源出现模型密钥。
12. STATUS／BACKLOG／测试证据把未执行能力写成已通过。

模型效果评测单独记录，不混入确定性单元测试。首轮建议至少覆盖 20 个固定生成样本；如果“一次生成 + 一次修复”的协议合规率低于 90%，暂停扩大功能，优先收紧生成契约或表现复杂度。该阈值是 P2 工程门槛，不代表通用安全性证明。

## 10. 明确不属于 P2

- Timeline 协议探测、鉴权和真实业务取数。
- 完整项目、成员、普通消息和上下文持久化。
- 自动上下文、长期记忆和后台摘要。
- active、查询复用、TTL、新鲜度、生成锁、热缓存和淘汰。
- 多文件代码依赖、ZIP 上传、多 runtime、viewer 动作 API。
- 无人访问时持续运行的后台生成任务。
- 发布、扩大访问范围或迁移真实生产数据。

## 11. 完成定义

P2 完成必须同时满足：用户可以按需生成新的非预置快照；服务端可信校验后使用 D1／R2 持久提交；生成记录可刷新回放；两种表现形态通过验收；失败、越权和恶意候选均 fail-closed；P1 全量回归通过；测试证据和事实状态已更新。此时只能声明“Agent 能基于测试／用户提供数据动态生成快照”，不能声明 Timeline 真实取数、生产协作权限或缓存已完成。
