# ADR-0004：用户项目与上下文是唯一连接状态

日期：2026-09-12

状态：Accepted

> 2026-09-22 澄清：本 ADR 禁止的是第二套部署级项目/连接注册表，不禁止把同一个真实项目的名称、tag、上下文和对话作为一个服务端聚合持久化。生产 DAO tag 准入必须使用该服务端记录；用户-tag 权限关系仍由 DAO 判断。当前执行计划见 `docs/PRODUCTION_RELEASE_PLAN.md`。

## 背景

项目由用户持续新建和删除。如果服务器另外维护项目配置、Timeline 连接注册表或看板映射，会与真实项目生命周期重复，删除后容易留下不可维护的垃圾状态。项目群聊还错误地把项目上下文当成话题限制，导致 DeepSeek 拒绝回答工作无关问题。

## 决策

1. 项目由用户创建、重命名和删除；删除项目同时删除其对话和上下文。
2. 服务器端的项目状态只包含项目对话与项目上下文，不维护独立项目注册表或 Timeline 连接注册表。
3. Timeline 地址、看板 ID 和访问密码写在项目上下文中；有完整连接上下文时宿主可以提供只读 Timeline 工具，没有时不能访问。
4. Timeline 密码保留在项目上下文原始记录中，仅在宿主侧使用；发送给 DeepSeek 的临时副本会替换为脱敏标记，也不写入快照或错误响应。
5. 用户在同一上下文窗口新增、修改或删除连接字段，访问能力立即同步变化，不产生第二份配置。
6. 项目上下文只提供额外背景，不限制聊天主题。普通对话直接交给项目配置的 DeepSeek 模型回答。
7. 公司 OAuth 与 DAO 项目 tag 准入负责谁能进入项目；第一阶段通过准入的用户在项目内同权，不另建分级权限。不改变单一上下文数据模型。

## 结果

项目和连接配置共享同一个生命周期，删除时不会遗留第二套配置。当前无持久化版本只在页面内保存项目、对话和上下文；生产持久化时也应按同一项目记录或级联删除实现。
