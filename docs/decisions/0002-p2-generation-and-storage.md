# ADR-0002：P2 使用 Sites D1/R2 与服务端受控生成

状态：Superseded in part by ADR-0003

日期：2026-09-11

决策人：产品负责人确认，开发方案据此执行

2026-09-12 说明：D1/R2 仍是已实现的存储适配器原型，但不再是首发、Timeline 接入或公司 OAuth 的前置条件。新的生产顺序和无状态首发边界见 ADR-0003；本文其余信任边界和候选校验规则继续有效。

## 问题

P2 要让 Agent 动态生成完整快照，并保证结果可验证、不可覆写、按项目隔离且能在模型离线时回放。现有 P1 只有构建期 dummy 目录；模型仅返回文本，项目和消息仍在浏览器内存。

## 决定

1. 保留当前 Sites／Cloudflare Worker 形态。D1 保存 run、可信目录和消息快照引用；R2 保存 manifest 与资源字节。
2. 模型只输出不可信 `SnapshotDraft`。可信 ID、scope、query 来源、时间、hash、状态和权限由服务端产生或核对。
3. 候选复用 P1 的 pack／validate 链路。所有对象写入并核对后，D1 才登记 committed；未登记对象不可读取。
4. 按需生成。普通交流只回文本；明确要求快照时失败必须明确报告。
5. P2 通过项目生成记录支持刷新后回放，不提前实现完整群聊消息持久化。
6. static dummy 与 dynamic snapshot 双轨共存。P4 之前不实现 active、TTL、复用和淘汰。

## 被否决方案

- 应用内 SQLite 与运行期本地文件：不符合已注册 Sites 项目的持久化能力和跨发布耐久要求。
- 前端直接提交到第三方托管存储：削弱服务端校验后提交的不变量。
- 模型直接生成可信 manifest 或写存储：模型输出不能授予权限或可信状态。
- 为 P2 提前实现完整项目／成员／消息系统：扩大到 P3 范围，阻塞动态快照主链路。

## 后果

- `.openai/hosting.json` 需要声明 `DB` 与 `BUCKET`，并新增不可改写的 Drizzle 迁移。
- 本地测试需要 D1/R2 兼容替身或受控测试环境；生产代码只通过小型存储模块访问绑定。
- R2 可能存在未登记的孤立对象，但它们不能被引用；清理与保留策略在 P4 完成。
- 幂等保证本产品不重复提交，不承诺供应商在异常窗口绝对不重复计费。
