# 序言 · 统一后续开发与生产发布计划

更新日期：2026-09-27

状态：执行计划；尚未达到生产发布条件

本文件是阶段顺序、当前阶段、下一步和发布门槛的唯一执行依据。`PRD.md` 定义产品目标，`docs/STATUS.md` 记录已验证事实，`docs/BACKLOG.md` 跟踪任务；`docs/DAO_OAUTH_PROJECT_ACCESS_PLAN_2026-09-15.md` 保留 DAO 协议与授权细节，`docs/PRODUCTION_RELEASE_PLAN_2026-09-12.md` 保留旧版历史背景。两份旧计划与本文件冲突时，以本文件为准。

## 1. 目标与边界

首发链路是：真实 DAO 用户登录 → 进入团队共享的真实项目 → DeepSeek Agent Runtime 按该项目上下文访问 Timeline 等数据源 → 自由对话或生成可核对的快照 → 通过统一校验后在隔离 viewer 展示。所有已登录员工均可访问站内项目；项目级 DAO tag 授权后移。

项目可以有多个数据源；服务器不建立按项目或数据源类型的连接注册表。项目上下文是背景、接入说明和第三方凭据的唯一配置入口。DAO OAuth 决定能否进入网站；首发所有已登录员工对站内项目同权。Agent 的第三方操作仍由上下文、用户指令、宿主受控工具和目标系统协议决定。

**首发必须持久化最小项目聚合**（项目 ID、名称、上下文、对话、创建者及时间）；否则客户端可自报上下文，也无法在重启后保留真实项目。首发同时加入项目级、只读文本问答缓存，用于跨员工复用高频问题的已验证答案。快照包、消息快照引用与生成运行记录的跨会话回放，以及快照缓存、Redis/共享 session 与多实例高可用后移。单实例内存 BFF session 可以用于首发，重启后重新登录；项目与问答缓存不能随重启消失。具体存储产品待阿里云选型，不预设 D1/R2。

## 3. 当前验收：Phase 2 最小项目聚合

### 开发方案

1. 建立平台无关的 `ProjectRepository`；由服务端生成不可复用 ID，持久化项目名称、加密上下文、共享对话、创建者及时间。项目、上下文、对话和附属缓存按同一个项目生命周期管理。
2. 所有项目 API 和聊天入口只信任 DAO BFF session；聊天请求只提交项目 ID 与消息，由服务端加载上下文。所有已登录员工可以列出、进入和操作站内项目，操作记录保留真实 actor ID；第三方数据源的宿主边界不随此共享范围扩大。
3. 删除项目时级联删除其上下文、对话和缓存；修改上下文时增加版本并使该项目旧缓存失效。替换演示项目、成员和客户端自报的项目事实。

### 测试范围与退出条件

- 重启后项目、上下文和对话保留；两名不同的 DAO 已登录员工可以访问同一项目，未登录或过期 session 不能访问项目或缓存。
- 浏览器篡改项目名称、上下文或 actor ID 不改变服务端可信项目；删除后项目与附属数据均不可访问，旧项目 ID 不复用。
- 上下文中的密码在存储、模型输入、快照、日志与错误响应中的保护符合现有秘密引用边界；`npm run check`、`npm run test:e2e` 及真实 DeepSeek/Timeline 回归通过。

## 4. 后续阶段与依赖

### Phase 1/3 · DAO tag 与成员契约、项目准入（首发后再决定）

首发所有 DAO 已登录员工均可访问站内项目，因此不读取 DAO tag 来做项目准入，也不建立本地用户-tag 权限关系。若未来决定按 tag 限制项目访问，再取得稳定 user/tag ID、成员接口和 `allow`／`deny`／`not_found` 三态真实契约，并对列表、项目、对话、上下文、Agent 与缓存统一授权；不能凭 tag 列表缺失推断 `not_found`。未来引入限制时必须使已有缓存随权限边界重新分区或失效。

### Phase 2 · 最小真实项目聚合持久化（当前）

按第 3 节执行。共享项目分别记录 `tenantId/projectId/actorId`，不能继续把 actor ID 当 tenant ID。服务端加载上下文并将第三方秘密替换为临时宿主引用；不建独立 Timeline 连接表。快照历史持久化仍不在本阶段。

### Phase 4A · 宿主安全与真实 Agent/数据验收

先收口宿主工具边界：秘密引用绑定单个数据源和允许的使用范围；所有返回模型的字符串替换已知秘密；HTTPS 目标同时通过服务端出站策略与解析后地址检查，内部系统只在明确受控范围内开放；change-set 的审计 actor 由宿主绑定当前 DAO 身份。以跨数据源、普通字段泄密、回环/私网、伪造 actor 的反例测试证明修复。随后在共享项目中验证 DeepSeek Agent 的真实 Timeline 读取及受控 change-set 写入。写入仅在专用测试看板和明确测试指令下执行，检查 base version、幂等键、commit 状态与写后回读；不得拿真实生产看板做未授权改动。再验收至少两种真实快照表现、空/边界输入、来源与观察时间、普通话题自由对话，以及多数据源工具边界。第二种外部数据源的真实端到端验收需等用户提供对应上下文，不把某个尚未提供的具体系统作为首发硬门槛。所有第三方操作继续受项目上下文和宿主工具约束。测试 URL/方法越权、伪造来源、快照校验失败和 viewer 隔离。

### Phase 4B · 跨员工共享的只读问答缓存（首发前）

先采集不含提示词、密钥和响应正文的每轮 token 用量、工具调用、耗时与缓存命中率，按普通对话、Timeline 读取和快照任务形成基线。首版只缓存已完成且通过脱敏检查的**独立、只读文本问答**；第三方写入、依赖上文的追问、WebSearch 时效信息和快照包均不命中。以项目 ID、上下文版本、规范化独立问题、模型/提示词版本和数据源范围构成缓存身份；只对已确认可独立复用的高频问法做精确匹配，不以关键词路由普通 Agent 对话，也不把语义相似当成等价。缓存保存答案、数据来源、原始观察时间、有效期和命中统计；命中时明确展示“缓存答案／数据截至时间”，不得把旧答案描述为实时取数。提供显式“重新查询”入口。动态项目数据初始采用 5 分钟硬过期，按实际数据变化和团队可接受的新鲜度调整。项目上下文变更、删除或宿主确认的写入立即失效；第三方系统绕过本站修改时依靠有效期限制陈旧，超期必须重新调用 Agent。缓存条目与项目同库存储，按过期时间和项目删除清理；对同一问句的并发未命中进行合并，避免重复调用模型。测试两名员工跨会话命中且命中时零 Agent 调用、上下文/写入失效、超期重取、跨项目隔离、不同历史追问不误命中、未登录无法取缓存，以及无密钥/旧数据冒充实时结果。以实际命中率、token 节省、时延和答案正确率评估效果；若高频问法不够独立，再设计可审阅的 FAQ 入口，不盲目扩大自动匹配。

### Phase 5 · 阿里云预发布与小范围生产

确认支持 Node 子进程的单实例运行产品、项目数据库、域名/TLS、DAO 回调、出站网络、密钥托管、日志脱敏、健康检查与回退。为 Agent 设置整机、项目、用户三级并发上限和排队上限，取消前检查、TERM 后强制 KILL、进程树与临时目录清理；收窄子进程环境变量。明确任务级 OS 隔离部署方案并验证文件、进程、网络与资源边界，不能把独立 PID 或 Claude Code 的工具权限当成沙箱。以目标实例的真实文本、取数、快照任务做 1/2/4 并发阶梯压测，记录内存、CPU、时延、失败率、模型限流、成本和故障互扰，据实确定首发上限，不预设已支持的生产并发数。验证反向代理不缓冲 `/api/chat` 事件流；执行真实 OAuth → 共享持久项目 → DeepSeek Agent/问答缓存 → Timeline/其他数据源 → 快照 viewer 的端到端回归，并做重启、登录失效、数据源失败、缓存过期、超时任务和回退演练。通过后仅向已登录内部用户小范围开放。

### 发布后 · 只读定时自动化（独立阶段）

在首发线上基线稳定、DAO 确认服务身份或用户委托及撤权语义之后，第一版仅允许只读文本任务。调度器只提交不含秘密的任务 ID 和计划触发时间；服务端重新验证有效登录/委托，从可信项目聚合加载上下文，先持久化 `scheduleId + plannedFireTime` 唯一运行记录及租约，再调用受控 Agent。交互与定时任务共用整机资源上限，交互请求优先；任务停用、项目删除和授权失效后不得继续触发或重试。保存结果、错误、用量与审计字段，并验收重复触发、崩溃恢复和撤权。定时快照另依赖不可变快照包和结果引用持久化；定时外部写入另需明确授权、目标系统幂等与写后回读，不纳入只读首版。

### 发布后 · 快照持久化与性能优化

持久化不可变快照包与消息引用，恢复刷新和跨会话回放；随后依据真实延迟、调用量与 token 成本设计快照生成幂等恢复、active 指针和快照缓存。只读文本问答缓存已提前列入 Phase 4B，不等同于快照包持久化。若只读定时文本任务先上线，其最小运行记录与结果必须单独持久化，不能借用未上线的快照存储。多实例/HA 前再将 BFF session 升级为共享存储。

## 5. 生产发布阻断项与证据规则

未登录用户仍能读项目/对话/快照/缓存或启动 Agent、项目上下文仍由客户端自报、演示数据冒充真实数据、跨数据源秘密串用或敏感值泄露、模型绕过受控工具、私网出站策略缺失、审计 actor 可伪造、缓存串项目或旧答案冒充实时数据、整机并发/子进程硬回收未验收、任务级隔离边界不清、未经校验的快照执行、真实来源无法核对、阿里云纵向回归/回退缺失，任一项都阻断发布。DAO tag 三态及项目级准入只有在未来启用 tag 限制时才成为该功能的发布门槛。

每阶段都更新 `docs/STATUS.md`、`docs/BACKLOG.md` 和测试证据，区分“代码已实现”“自动化通过”“用户报告真实验收通过”“脱敏证据已归档”。未执行的 DAO tag、Timeline 写入、缓存或阿里云测试不得记为通过。后续开发和外部写入按用户授权范围进行；本计划本身不授权操作第三方生产数据。
