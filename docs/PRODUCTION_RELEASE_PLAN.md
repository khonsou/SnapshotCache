# 序言 · 统一后续开发与生产发布计划

更新日期：2026-09-22

状态：执行计划；尚未达到生产发布条件

本文件是阶段顺序、当前阶段、下一步和发布门槛的唯一执行依据。`PRD.md` 定义产品目标，`docs/STATUS.md` 记录已验证事实，`docs/BACKLOG.md` 跟踪任务；`docs/DAO_OAUTH_PROJECT_ACCESS_PLAN_2026-09-15.md` 保留 DAO 协议与授权细节，`docs/PRODUCTION_RELEASE_PLAN_2026-09-12.md` 保留旧版历史背景。两份旧计划与本文件冲突时，以本文件为准。

## 1. 目标与边界

首发链路是：真实 DAO 用户登录 → 进入其获准的真实项目 → DeepSeek Agent Runtime 按该项目上下文访问 Timeline 等数据源 → 自由对话或生成可核对的快照 → 通过统一校验后在隔离 viewer 展示。

项目可以有多个数据源；服务器不建立按项目或数据源类型的连接注册表。项目上下文是背景、接入说明和第三方凭据的唯一配置入口。DAO 只决定用户能否进入项目；进入后第一阶段不另设项目内操作角色，Agent 的第三方操作仍由上下文、用户指令、宿主受控工具和目标系统协议决定。

**首发必须持久化最小项目聚合**（项目 ID、名称、tag、上下文、对话、创建者及时间）；否则客户端可自报 tag／上下文，DAO 项目准入无法可信执行，也无法在重启后保留真实项目。**仍后移**的是快照包、消息快照引用与生成运行记录的跨会话回放，以及查询缓存、TTL、active、Redis/共享 session 与多实例高可用。单实例内存 BFF session 可以用于首发，重启后重新登录；项目本身不能随重启消失。具体存储产品待阿里云选型，不预设 D1/R2。

## 3. 下一步：Phase 0 真实 DAO OAuth 收口

### 开发方案

1. 在 DAO 已登记回调的 HTTPS 环境部署现有单实例 Node/BFF；确认实际访问域名、精确 `redirect_uri`、authorize/token 端点和 `profile phone` scope。按 DAO 真实契约核对当前“不发送 `client_id`、从 token JWT 获取 `user_id/user_name`”实现；如果真实响应不同，以脱敏实测为依据调整，不猜测参数，也不把 mock 契约当生产契约。
2. 使用服务端安全配置注入 DeepSeek key 和 OAuth 设置；生产关闭测试身份绕过、HTTP OAuth 和调试输出。浏览器只持有 HttpOnly/Secure 同源 session cookie；OAuth token 不进入页面、项目上下文、Agent 或日志。
3. 保持现有项目与 Agent 行为不变：此阶段不读 DAO tag，不改变项目授权逻辑，不借登录门禁声称已经完成项目级隔离。修复真实联调暴露的问题，更新环境模板、状态和测试证据。
4. 若 DAO 目前只登记生产回调，优先由 DAO 增加受控预发布 HTTPS 回调；如必须在正式回调域名验收，采用受控小范围测试部署。没有可用的真实 HTTPS 回调时，Phase 0 保持未完成，可并行做 Phase 1 契约调研，但不能跳过真实验收。

### 测试范围与退出条件

- 自动化：PKCE S256、state、一次性 transaction、同源 return path、过期/伪造 cookie、code 重放、OAuth 错误、跨站退出、身份 header 伪造、生产禁用测试绕过；`npm run check` 与 `npm run test:e2e` 全量回归。
- 真实 DAO 手工：至少一名员工完成登录 → `/api/session` → 刷新保留登录 → 原有对话/快照 → 退出 → 旧 cookie 被拒绝；未登录和过期 session 调用受保护 API 返回 401；服务重启后可重新登录。
- 安全核对：浏览器存储/网络响应、Agent 输入、快照、普通日志与错误响应均无 OAuth token；精确回调、Secure/HttpOnly cookie、生产 HTTPS 和 DeepSeek 模型配置在目标环境生效。
- **退出条件**：上述真实 DAO HTTPS 链路通过并留存脱敏证据。仅本地 mock、单元测试或页面显示“已登录”均不构成通过。

## 4. 后续阶段与依赖

### Phase 1 · DAO tag 与成员契约确认

取得真实脱敏响应，确认稳定 user/tag ID、tag 重命名语义、DAO 成员接口，以及用户态批量 `allow`／`deny`／`not_found` 三态判断。不能凭 `/api/task-tag` 列表缺失推断 `not_found`。测试允许、拒绝、明确不存在、DAO 故障与畸形/缺项响应；无法区分 deny 与 not_found 时，项目 tag 授权不得上线。本阶段可与 Phase 0 真实回调准备并行，但不能把未验证契约写成已实现。

### Phase 2 · 最小真实项目聚合持久化

建立平台无关 `ProjectRepository`，服务端生成不可复用 project ID，保存名称、tag、加密上下文、对话、创建者和时间；不保存永久的用户-tag 权限关系，不建独立 Timeline 连接表。聊天只提交 project ID 与消息，服务端加载上下文并将第三方秘密替换为临时宿主引用。删除项目级联删除上下文、对话、tag 与相关授权租约。共享项目的 `tenantId/projectId/actorId` 分离，不能继续把 actor ID 当 tenant ID。测试重启保留项目、篡改客户端 tag/context 无效、跨项目读取拒绝、删除后不可访问、秘密不落明文日志或模型提示词。快照历史持久化仍不在本阶段。

### Phase 3 · DAO 项目准入与 GUI 全真

项目默认无 tag，允许所有 DAO 已登录员工访问；自定义 tag 只有在 DAO **明确**返回 `not_found` 时才不限制访问。一个项目可绑定多个 tag，任一 `deny` 即拒绝；DAO 超时、未知结果或租约过期均不得放行。默认使用最长 10 分钟的项目访问租约，且不超过 session/token 期限；修改 tag、退出和 session 轮换立即失效。项目列表、详情、CRUD、上下文、聊天、快照与 Agent 启动均由服务端项目准入保护。GUI 提供 tag 多选、开放范围警告，并移除生产演示成员/项目数据；成员只读展示待 DAO 接口确认。测试无 tag、未知 tag、多 tag 一票否决、撤权、过期、DAO 故障、跨用户/跨项目和直接 API 绕过。

### Phase 4 · 真实 Agent/数据与快照验收

先收口宿主工具边界：秘密引用绑定单个数据源和允许的使用范围；所有返回模型的字符串替换已知秘密；HTTPS 目标同时通过服务端出站策略与解析后地址检查，内部系统只在明确受控范围内开放；change-set 的审计 actor 由宿主绑定当前 DAO 身份。以跨数据源、普通字段泄密、回环/私网、伪造 actor 的反例测试证明修复。随后在已获准项目中验证 DeepSeek Agent 的真实 Timeline 读取及受控 change-set 写入。写入仅在专用测试看板和明确测试指令下执行，检查 base version、幂等键、commit 状态与写后回读；不得拿真实生产看板做未授权改动。再验收至少两种真实快照表现、空/边界输入、来源与观察时间、普通话题自由对话，以及多数据源工具边界。第二种外部数据源的真实端到端验收需等用户提供对应上下文，不把某个尚未提供的具体系统作为首发硬门槛。所有第三方操作继续受项目上下文和宿主工具约束，不由 DAO tag 扩权。测试 URL/方法越权、伪造来源、快照校验失败和 viewer 隔离。

### Phase 5 · 阿里云预发布与小范围生产

确认支持 Node 子进程的单实例运行产品、项目数据库、域名/TLS、DAO 回调、出站网络、密钥托管、日志脱敏、健康检查与回退。为 Agent 设置整机、项目、用户三级并发上限和排队上限，取消前检查、TERM 后强制 KILL、进程树与临时目录清理；收窄子进程环境变量。明确任务级 OS 隔离部署方案并验证文件、进程、网络与资源边界，不能把独立 PID 或 Claude Code 的工具权限当成沙箱。以目标实例的真实文本、取数、快照任务做 1/2/4 并发阶梯压测，记录内存、CPU、时延、失败率、模型限流、成本和故障互扰，据实确定首发上限，不预设已支持的生产并发数。验证反向代理不缓冲 `/api/chat` 事件流；执行真实 OAuth → DAO 项目准入 → 持久项目 → DeepSeek Agent → Timeline/其他数据源 → 快照 viewer 的端到端回归，并做重启、DAO 故障、数据源失败、超时任务和回退演练。通过后仅向授权内部用户小范围开放。

### 发布后 · 只读定时自动化（独立阶段）

在首发线上基线稳定、DAO 确认服务身份或用户委托及撤权语义之后，第一版仅允许只读文本任务。调度器只提交不含秘密的任务 ID 和计划触发时间；服务端重新验证项目准入，从可信项目聚合加载上下文，先持久化 `scheduleId + plannedFireTime` 唯一运行记录及租约，再调用受控 Agent。交互与定时任务共用整机资源上限，交互请求优先；任务停用、项目删除和授权失效后不得继续触发或重试。保存结果、错误、用量与审计字段，并验收重复触发、崩溃恢复和撤权。定时快照另依赖不可变快照包和结果引用持久化；定时外部写入另需明确授权、目标系统幂等与写后回读，不纳入只读首版。

### 发布后 · 快照持久化与性能优化

持久化不可变快照包与消息引用，恢复刷新和跨会话回放；随后依据真实延迟、调用量与 token 成本设计生成幂等恢复、查询复用、TTL、active 和缓存。若只读定时文本任务先上线，其最小运行记录与结果必须单独持久化，不能借用未上线的快照存储。多实例/HA 前再将 BFF session 升级为共享存储。不能把这些后移能力写成已上线。

## 5. 生产发布阻断项与证据规则

真实 DAO 登录未验收、DAO tag 三态不明确、项目 tag/context 仍由客户端自报、拒绝项目仍能读对话/快照或启动 Agent、演示数据冒充真实数据、跨数据源秘密串用或敏感值泄露、模型绕过受控工具、私网出站策略缺失、审计 actor 可伪造、整机并发/子进程硬回收未验收、任务级隔离边界不清、未经校验的快照执行、真实来源无法核对、阿里云纵向回归/回退缺失，任一项都阻断发布。

每阶段都更新 `docs/STATUS.md`、`docs/BACKLOG.md` 和测试证据，区分“代码已实现”“自动化通过”“mock 人工通过”“真实外部系统通过”。未执行的真实 OAuth、DAO tag、Timeline 写入或阿里云测试不得记为通过。后续开发和外部写入按用户授权范围进行；本计划本身不授权操作第三方生产数据。
